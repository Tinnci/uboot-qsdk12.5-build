# AX5 JDCloud — experimental container-built U-Boot

## Status / 状态

**Experimental, NOT hardware-boot-tested. Do not treat this as a recommended
upgrade or a verified recovery image.**

这是容器编译基线，不是已经通过真机启动测试的稳定版本。未刷写路由器，
未验证串口、网口、Reset 恢复入口、实际刷写或自动回退。

## Device and artifact

- Device: Redmi AX5 JDCloud / RA50, IPQ60xx (IPQ6018 configuration).
- Build target: `redmi_ax5-jdcloud`.
- Defconfig: `ipq6018_redmi_ax5_jdcloud_defconfig`.
- Do NOT use on ordinary Redmi AX5, other JDCloud models, or another board.
- Image: `uboot-ipq60xx-redmi_ax5-jdcloud-261025_005307_9ce3157.bin`.
- Final size: 655,360 bytes (640 KiB).
- Packaged image before padding: 510,010 bytes.
- Format checked: ELF32, little-endian, ARM.
- SHA-256:
  `90d4304f7de05dfb87c3f675a881e22cf5cb3ceced657d915e12356ded9655d7`.

The `.bin` is the Qualcomm-packaged U-Boot image, not an OpenWrt sysupgrade,
factory image, complete eMMC image, GPT, or boot environment backup.
Do not upload it to an OpenWrt firmware-upgrade page.

## Isolation and Git fixes

Host source and Git object inputs are mounted read-only. Compilation takes
place in a disposable Linux filesystem, with a separate writable output mount.
Git metadata and borrowed objects are copied locally; this avoids partial-clone
lazy-fetch stalls and macOS-only alternate-object paths. No host SSH agent,
router device or credentials are forwarded.

Build pipeline: defconfig -> `make V=s` -> strip ELF ->
`elftombn.py` (IPQ60xx MBN version 6) -> pad to 640 KiB.
Qualcomm hash packaging is not proof of a vendor-authorized secure-boot signature.

## Flashing and recovery limitations

Do not flash solely because compilation passed. First confirm exact board,
secure-boot policy, image format, partition sizes, serial access and a recovery
method independent of the U-Boot being replaced.

Back up GPT, BOOTCONFIG, APPSBL/APPSBL_1, APPSBLENV, ART and other critical
boot firmware to another device. Keep personal data backups separately.
No device-specific partition dumps are included in this public release.

On the inspected device, APPSBL and APPSBL_1 are each 640 KiB; the secondary
slot is all zero. Filling that slot does NOT establish automatic fallback.
The installed 2022 U-Boot is not proven to behave like this newer source.
The newer source's Web updater can write both U-Boot slots; inspect it before use.

Do not erase BOOTCONFIG, replace GPT, overwrite ART/CDT/SBL, or change both
bootloader copies as an incidental step. A broken U-Boot cannot provide its
own Web recovery; deeper rescue may be necessary.

This release does not implement Linux A/B success marking or rollback.
Linux HS400 initialization failure happens after U-Boot and is not fixed by
having a second bootloader image. This is not an HS400 U-Boot modification.
